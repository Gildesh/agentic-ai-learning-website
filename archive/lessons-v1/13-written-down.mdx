Next Sunday the clock starts a beat. The helper is fresh. It opens all three links again, including the library page that failed. It drafts as if Sam had never accepted a two-source brief. The old chat, if it still exists somewhere, is not on the desk. The model starts blank. Sunday feels like the first Sunday, because nothing outside the model told it otherwise.

## The note that survives the broom

The spine is a saved note, outside the model, of what is done, what is next, and what is waiting on a person. The beat reads it first and writes it last. Read first, so the plan can avoid settled work. Write last, so the next Sunday is not blank. A conversation is not this note. You can scroll a conversation only while that conversation is the desk. A new beat sweeps the desk. The note is in the drawer until the beat places it on the desk on purpose, as the first paper.

Here is Sam's note after the Sunday you have been walking. It is a note, not a program. You could copy it into any notes app.

```text
Job: Sunday study digest
Done: 2026-09-27 brief saved. Link 3 failed. Sam accepted two sources.
Next: On Sunday, open new links only. Keep the accepted gap for link 3.
Waiting on Sam: nothing, unless a new link asks to email the brief.
Finish line: one page; each source named; one sentence each; every gap written.
Try count last time: 2 of 3. Last checker: pass.
```

Count the lines. Job. Done. Next. Waiting on Sam. Finish line. Try count and last checker. That is the spine. It is short because a long spine becomes another cluttered desk. The finish line is repeated here so a new beat does not have to hunt through last week's prose to find the test.

## What the next beat must leave alone

The note says link 3 failed and Sam accepted two sources. The helper must not treat link 3 as a new failure to solve. It must not expand the brief back to three sources unless Sam changes the note. "Unless Sam changes the note" is the important door. The spine is not a law above Sam. It is Sam's memory, written where a blank model can read it. If Sam later finds a replacement for link 3, Sam edits the note. The helper does not "improve" the decision by quietly reopening the hunt.

What does the beat read first? The spine. Then the saved instructions. Then the new links, if any. A beat that opens tools before it reads the note will redo settled work and call the redo thorough. Thorough, you already know, is not a finish line. The order is part of the skill: read the note, then act.

What does the beat write last? An updated spine. If nothing new arrived, the done line can stay, and the next line can say "no new links." If a new link arrived and was added, the done line names it. If the checker failed all three tries, the note says so, and it does not say pass. A spine that flatters the last run is as bad as a missing spine. The next Sunday will trust it.

## A second week, in miniature

Imagine 4 October. One new link is in the folder, about rehearsal and memory. The beat reads the note, leaves link 3 alone, opens only the new link, adds one sentence, and saves a new file in its own folder so it does not overwrite 27 September. Then it rewrites the done line: "2026-10-04 added the rehearsal article. Link 3 still an accepted gap." Waiting on Sam stays empty, because nobody asked to email.

If the beat had no spine, it would open the dead library page, draft three sources, and perhaps overwrite the September file. Every failure you can name from the six-part picture would be available at once. The spine is the part that makes "next Sunday" a continuation instead of a reboot.

The conversation history is a tempting substitute because it is already full of detail. It is the wrong object. History is long, it may not be on the desk, and it mixes the trip, the grade complaint, and the real decision. The spine is the decision, distilled. When you feel the urge to paste the whole chat "so it remembers," write six to eight lines instead. You are building the drawer the broom cannot sweep.

## Update the note after a quiet week

Suppose the next Sunday brings no new link. A careless beat might invent work, or might leave the old note untouched and also leave no sign that it looked. Write the update anyway. Done: looked on the new date, no new link, link 3 still an accepted gap. Next: look again next Sunday. Waiting on Sam: nothing. The finish line stays copied at the bottom so it cannot drift. Try count can say "no draft this week."

That quiet update is how you know the clock fired. An unchanged file from weeks ago might mean the loop is wise, or it might mean the loop is dead. A line with today's date is the difference. Practice writing that quiet note once, by hand, so a blank model is not the only author of memory. If you let the maker write the spine alone, ask the checker to see the note too, or read it yourself the first Sundays. A spine that says pass when the checker failed is a new kind of gap, and next week will obey it.

Read last week's note before you celebrate a new brief. If the new brief reopens link 3, the beat did not read the note, or the note was not on the desk. If the note says pass and you can see a missing gap, the note is flattering and should be corrected before next week trusts it. The spine is a tool for continuity only when it tells the truth. A false done-line is worse than a blank one, because a blank one looks empty and a false one looks settled. Settled is what the next beat will obey.

Copy the sample note by hand once, including the date and the accepted gap. Hand copying makes you notice which line would be dangerous if it were wrong. The done line is dangerous when it flatters. The next line is dangerous when it is vague. Waiting on Sam is dangerous when it hides an email that already went out. A good spine is a little dull. Dull means the next beat can obey it without inventing a drama. Drama belongs in the articles, not in the memory of what Sam already decided.
