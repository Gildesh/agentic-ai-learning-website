This lesson adds no new part. It runs one Sunday in order, using only the pieces you have already named. If a sentence introduces a gadget, it does not belong here. The point is sequence. You should be able to tell the story without looking, and then check yourself against the page.

## Sunday, in order

The clock is the heartbeat. At 09:00 a beat starts. Sam is asleep. The laptop lid can be closed, because the clock does not live inside Sam's chat box.

The beat reads `sunday.md` first. That file is the spine. It says the job is the Sunday study digest. It says link 3 failed last time and Sam accepted two sources. It says the next work is new links only. It repeats the finish line. It records the last try count and whether the checker passed.

Saved instructions sit beside the spine. They say Sam's format: one page, one sentence per source, a gap line for a link that did not open, the date written as 12 May. The beat does not invent a letter to the teacher. The format is already written.

The working folder is a new file for this Sunday, not an overwrite of last week's brief. Last Sunday remains on disk under its own name. This Sunday will save beside it. Two runs will not delete each other.

The connector runs. Open page is allowed. The beat opens the new links, and it does not reopen link 3 as a problem to solve. In the walk you already did, link 3 fails. Keep that same failure in mind as the reason the spine says what it says. If a new link fails this Sunday, the plan changes. The plan becomes: sentences for the links that returned text, plus a written gap for the one that did not. The finish line does not change.

`/goal` repeats the writing beat until the bar passes or three tries hit. The card is filled. Finish line: the checklist. Try limit: three. Who checks: a different pass. The maker writes a draft in the new file. The checker is a different pass with the three bars: sources or written gaps, one sentence per source, no claim without a source. The maker's "Done!" is not consulted.

Suppose the first draft forgets a gap and the checker fails. The second draft adds the gap and passes. The loop stops because the line is true, not because the try limit was exhausted. The try count, 2 of 3, is ready to be written into the spine. If the third try had also failed, the stop would be the limit, and the spine would say the checker did not pass. A saved failure is still an honest Sunday.

On a pass, save note writes the brief into the new file and updates the spine. The done line includes "Link 3 failed. Sam accepted two sources," and it adds whatever this Sunday actually did. The next line says what the following Sunday should pick up. Waiting on Sam stays empty unless a send is proposed.

Email stays behind the human gate. The brief can be excellent and still not be an email. The wrapper does not offer send as an allowed tool. If a draft of an email exists as text, it waits. Sam will see it later and say yes or no. A checker pass does not press send.

## Where people shuffle the scraps

A tired retelling puts the checker first, because the grade feels like the climax. The grade is late. Nothing can be graded before there is a draft, and there is no draft before a beat starts and reads what is already settled. Another retelling puts the email in the middle, as a sign of helpfulness. Helpfulness does not move the gate.

Put these scraps in order: checker pass, clock, read spine, open page, human gate before email. The order is: clock, read spine, open page, checker pass, human gate before email. The maker's drafts sit between open page and the checker pass, inside the tries. The spine is written again after the pass, before anyone dreams of sending. If you can repair a shuffled list, you have the Sunday.

Why is the gate still there after a pass? Email is the action Sam did not pre-approve. A pass grades the brief. It does not grant a new permission. You can say that sentence from two earlier lessons at once, the wrapper lesson and the checker lesson. This Sunday is where they share a single moment.

## The same shape, different work

A programmer's morning bug list uses the same six parts with different tools. A clock or a doorbell starts it. A note says which bugs were already handled. Instructions say how a change should be described. Each job is written in its own folder so two fixes do not trample one file. A connector talks to the bug list and the code store. A maker writes a change. A checker runs a test or a second pass against a bar. A human gate stands in front of publishing the change to everyone. You do not need to perform that morning. You need to see that the labels survived the change of costume. If a tutorial's commands confuse you later, sort them back into these parts. The commands are the costume.

## You still look, at first

Once the picture is complete, it is tempting to leave it forever. The first Sundays still get a look, because a weak checker can pass a bad brief. The bar can be too coarse. The maker can satisfy the letter of "one sentence" with a sentence that invents a number. The spine can be updated with a cheerful lie if you let the maker write the note alone. For the first few real Sundays, Sam reads the brief and the spine before trusting the clock. That reading is not a failure of the loop. It is how Sam learns whether the checker is strong enough to be left. Intent stays with Sam: the digest exists to support studying, not to impress a teacher. Accountability stays with Sam: if a false sentence goes into the notes, the clock does not attend class and explain it.

When the briefs are dull and correct for several weeks, Sam can look less often. Less often is earned. Never is a story people tell after one good demo.

## Tell the Sunday aloud

Close the page and tell the Sunday in one breath, then check yourself. Clock at 09:00. Read the spine. Read the format. Write in a new file. Open pages, and do not reopen link 3 as a problem. If something fails, bend the plan and keep the finish line. Repeat the draft until the checker passes or three tries are spent. On a pass, save the brief and rewrite the spine, including the accepted gap. Stop before email.

If you dropped the new file, you will overwrite last week. If you dropped the checker, "Done!" will sneak back in. If you dropped the gate, helpfulness will send the mail. Those three drops are the usual ones. Tell it again until none of them drop. Then look at a real brief the first time you ever let a clock do this, because a complete order can still hide a weak bar. The programmer's morning bug list can wait. Your mouth already has the shape it would use.
