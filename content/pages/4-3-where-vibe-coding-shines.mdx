<Hook>

You need a clickable list of books for a conversation tomorrow. No one will enter a card. No one will leave a password. If the page is wrong, you will close the laptop and describe it aloud instead. That folder is a prototype. The loop from the previous page is a fit.

</Hook>

## The idea

<Term id="vibe-coding">Vibe coding</Term> earns its speed when three conditions hold.

- **The audience is you, or a room you are standing in.** A demo can be narrated. You can say "ignore that button" out loud. A customer alone at midnight cannot.
- **The data is fake or disposable.** Titles you typed. A <Term id="repository">repository</Term> you will delete. Not someone else's orders.
- **Failure is cheap.** The worst case is embarrassment in the meeting, or an evening lost. It is not a charge, a leaked inbox, or a broken migration.

Internal tools sit on the border. A script only you run, on a copy of the data, is close to a prototype. The same script pointed at the live shop, with a button that deletes rows, is not. The folder did not change. The cost of a wrong run did.

Prototypes are allowed to be ugly and allowed to be unread, if you have labeled them as prototypes. Put that label in the README in one line: "Demo only. Do not enter real cards. Delete this folder after the meeting." Future you, and any agent you point at the folder next month, needs that line. An unlabeled prototype gets treated as a product because the screen looks like one.

When a prototype is promoted, the unread files come due. That promotion is a different kind of work. Page 4.10 is the list of what you add. Until then, keep the demo in its own repository so a later agent cannot "finish" it inside the real shop.

## Real example

A README line that makes the boundary visible:

```
Demo only, for the Tuesday conversation.
Titles are hard-coded. There is no login and no payment.
Delete this repository after the meeting.
```

If you cannot write that paragraph truthfully, the folder is not a vibe-coding candidate. It needs the diff review from Part 3 before anyone else opens it.

<TryIt minutes={5}>

Pick a thing you have wanted an agent to build. Write the three conditions as yes or no: narrated audience, disposable data, cheap failure. Three yeses means a scratch repository. Any no means you stop at a sketch, or you read the files. Write which one you chose.

</TryIt>

<Mistake>

Building the demo inside the real project's repository "so it is easy to keep." The agent will edit real files because they are in the window. A demo gets its own folder. Keeping it is a later, explicit copy of the pieces you still want.

</Mistake>
