## The idea

One prompt can draft a product. It cannot remember the spec, the check, or the commit. The lap is spec, task, build, check, commit. The spec lives in a file you name, such as `docs/SPEC.md`. The tool does not open that path unless a rule or a message names it.

A card has one job, an allow-list of files, and a check. A fast model can finish a small card. It cannot invent the product safely. Lock the test in an earlier commit. The implementation diff that touches the test has failed.

A gate is a command and an exit code. Run it. A stop hook, the agent hook from Part 3, can run it when a turn ends. Cursor's `stop` event can send a follow-up, with a default cap of five. Claude Code's `Stop` hook can refuse to stop, and the guide caps consecutive blocks at eight. Leave the cap. The hook is not a React hook.

The maker edits. The checker reads the diff and the spec, or you run a command. After a couple of failures, mark the card blocked and escalate with the output, not with a blank prompt. Scope is `git diff --name-only` against the card. Parallel agents get disjoint files and separate branches. Merge a green branch, then the next.

Commit only a tree the gate accepted. A commit message does not make a red check green.
