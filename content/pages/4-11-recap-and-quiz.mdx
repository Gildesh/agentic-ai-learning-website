<Hook>

You can move fast on a disposable folder and still refuse to call a painted sentence a payment. That split is the whole part. The quiz checks whether you can tell the two apart.

</Hook>

## The idea

<Term id="vibe-coding">Vibe coding</Term> is describe, run, react, often without reading the code. Andrej Karpathy put the phrase on X on 2 February 2025. It fits a narrated demo, disposable data, and cheap failure. It does not fit a path you would be ashamed to delete.

React to a thing you saw, in one quote, after a reload. Keep each ask to one visible change and one check. The "90% done" wall is the list of inputs you have not tried.

<Term id="git">Git</Term> is the undo for a session you did not read. Commit before the experiment. Do not commit during it. `git restore` drops uncommitted files back to that snapshot.

A bug note carries the command, the error, the expected result, and the files that may change. Reading code you did not write starts at the entry the click hits, then one hop, then one input you choose.

The checkout case study is the warning. "Show Paid" produced a function that returned that word and sent no payment request. The honest ask was "show not connected, and do not add a card field." Promoting the folder means a written check, a diff on the dangerous path, and a commit message that admits what was not kept.

## Real example

Five lines, then the quiz.

1. Vibe coding skips reading, not running.
2. One ask, one check.
3. Commit before the careless session.
4. The entry function is the first reading.
5. The word Paid is not a charge.

<Mistake>
