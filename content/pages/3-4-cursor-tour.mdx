## The idea

Cursor's rules doc says rules are system-level instructions to <Term id="agent">Agent</Term>. They are included at the start of the model context. The model still does not remember you between requests. The rule text is how a project stays consistent.

The same doc names four places rules come from.

- **Project rules**, stored in `.cursor/rules`, version-controlled, scoped to the codebase. Each rule is a markdown file with frontmatter, and project rules use `.mdc` files. A rule can always apply, apply when the agent judges the description relevant, apply when a file matches a pattern, or apply only when you mention it.
- **User rules**, global on your machine, used by Agent chat.
- **Team rules**, from the dashboard, on Team and Enterprise plans.
- **AGENTS.md**, plain markdown in the project, described as a simple alternative to `.cursor/rules`.

Tab, in the hooks doc, is the inline-completion surface. Agent chat is the session where the agent loop runs. The hooks page separates them on purpose.

A <Term id="hook">hook</Term> is a custom script. Cursor's hooks doc says hooks observe, control, and extend the agent loop. You define them in `hooks.json` at the project or user level. They are processes that talk JSON over stdio, and they run before or after stages of the loop. They can observe, block, or modify behavior. Agent hooks fire during an agent session. Tab hooks fire for inline completions. A hook is how you stop a tool call you do not want, such as a command that prints a secret. The rule file asks the model. The hook can refuse the tool.

This page does not list Cursor's prices. The docs index is [cursor.com/docs](https://cursor.com/docs).

## Real example

A project rule that always applies, in the shape the rules doc describes: frontmatter plus instructions.

```
---
description: tax function rules
alwaysApply: true
---

Edit only tax.py when the task is tax.
Do not add a web framework.
Show the command output before you say the check passed.
```

Save it under `.cursor/rules` as an `.mdc` file if you are following project rules. If you want one plain file instead, the docs say `AGENTS.md` is that alternative. Do not keep two copies of the same sentence. They will drift.

<Mistake>

Putting a secret or a one-off traceback in a project rule. Rules are sent often, and project rules are committed. A standing constraint belongs there. A key and today's error do not.

</Mistake>
