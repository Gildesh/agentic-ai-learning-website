The rule was in the spec. The diff broke it. Somewhere a command should have exited 1. If you cannot name that command, the rule was still a request.

</Hook>

## The idea

Enforcement is a failing command. A linter, this repo's `npm run lint` via ESLint, catches the rules you configured. A formatter only handles layout. Types catch impossible values. Tests catch behavior. `npm run check:course` catches the lesson rules.

GitHub Actions runs those commands on push and on a pull request. Use `actions/checkout` v7 for a normal pull request. Do not check out a fork's code under `pull_request_target`. A pre-commit hook runs the fast command on the laptop before git writes the snapshot, and it is not cloned with the repo, so CI still has to run.

An agent hook is the other hook: Cursor's `hooks.json`, Claude Code's `PreToolUse` and `Stop`. Fail closed. Leave the stop cap. Do not let the agent delete the hook.

Locked files include the checker, the workflow, and the locked test. Secret scanning includes GitHub push protection, which blocks a detected secret before the push lands, and a local check because repository push protection is off until someone enables it. A checklist is four yes-or-no lines for what you have not automated. A new rule becomes a command you have seen fail, then a pre-commit hook and a workflow step.

<Mistake>

Calling the spec "enforced" because it is long. Length is not an exit code. Point at the command that fails, or admit the rule is still a request.

</Mistake>
