<Hook>

Each page is one idea, short enough to finish in a sitting. You do not have to read every paragraph at the same depth. You do have to know which depth you used, because later pages assume the idea, not the time you spent.

</Hook>

## The idea

Use the fast path when you need the shape of the idea and you will meet it again. Read the hook, look at the figure, read the mistake, and do the try-it if it takes less than five minutes. That is enough to follow the next page.

Use the deep path when the idea is new, or when you will direct an <Term id="agent">agent</Term> with it this week. Read the idea and the real example. Do the try-it against the app sentence you wrote on the [first page](/part/0/who-this-is-for). Open each bold term. The glossary definition is the one this course means. A vendor page may use the same word more loosely.

A <Term id="full-stack">full-stack</Term> page, such as the ones in Part 6, is a deep-path page the first time. The map page after this one is a fast-path page: you are learning the order, not a mechanism.

Pages that are not written yet appear in the sidebar as titles without links. Those titles are the plan. A link is a page you can read. Your browser stores which linked pages you mark read. There is no account on this site.

If a try-it fails because a product moved a button, use the vendor's own docs for the click-path and keep the idea from this page. Product details are dated `2026-09` in the page header. The mechanism is the part that should still be true after the button moves.

## The same page, two depths

Page 7.2 is [REST: methods, URLs and status codes](/part/7/rest-methods-and-status-codes). On the fast path you leave with three words: method, URL, status code, plus the two GitHub URLs in the try-it. On the deep path you also read why `POST /books` returns 201 while `GET /books/42` returns 200, and you can say why a 404 is not "the API is down."

Either path is valid. Mixing them up is not. If you only read the hook and then skip the try-it, you do not yet have the idea in your hands.

<TryIt>

Open the [course map](/). Pick the part title that names a hole you already have, such as APIs or security. If that part has a written page, read it on the fast path: hook, figure, mistake. If it has no written page yet, stay on the written pages in order. Order matters more than jumping.

</TryIt>

<Mistake>

Highlighting every sentence and doing none of the try-its. The try-it is the check. A full highlight and a skipped action means you recognized the topic. It does not mean you can direct an agent with it.
</Mistake>
