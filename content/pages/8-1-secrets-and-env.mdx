## The idea

A secret is a value that grants access: an API key, a database URL with a password, a webhook signing secret. It belongs in the environment of the process that needs it, not in source. The usual local file is `.env`. The <Term id="backend">backend</Term> reads it when the process starts. The browser bundle never imports it.

Git must not track that file. A line in `.gitignore` does the job:

```
.env
```

Commit a sibling, `.env.example`, that lists the names and leaves the values empty. A new teammate copies it to `.env` and fills the values from a password manager or the host's secret settings. The example is documentation. The filled file is a secret.

The host has its own place for the same names. A deploy reads those, not a file you uploaded from your laptop. Part 6's environments are why local, staging, and production do not share one `.env`.

If a real key was committed, rotating it at the vendor matters more than the next commit. The old value is in history. Treat it as published. Then remove it from the tree and check that `.gitignore` matches the filename you actually use, including `.env.local` if the tool writes that instead.

Stripe's testing docs say the same thing about live keys: store them in a secrets vault or environment variables, and do not store them in source checked into version control.

## Real example

`.env.example` for the bookstore:

```
STRIPE_SECRET_KEY=
DATABASE_URL=
```

`.env` on your machine has the values and is listed in `.gitignore`. `git status` does not show `.env`. If it does, do not commit. Run `git check-ignore -v .env` and fix the ignore rule until the file is ignored.

<TryIt minutes={5}>

In a repo you care about, run a search for `sk_live`, `sk_test`, and `whsec_`. If a real value appears in a tracked file, rotate that key before you do anything else. Then confirm `.env` is ignored.

</TryIt>

<Mistake>

Committing `.env` "just this once" because the example file felt incomplete. The example is supposed to be empty. The secret file is supposed to be absent from the commit.

</Mistake>
