## The idea

This project's Next.js docs say layouts and pages are Server Components by default. A Server Component can fetch data, read a database, and use secrets without sending that code to the browser. It can be an `async` function. It cannot use `useState`, `useEffect`, or `onClick`.

A Client Component is a file whose first line is `'use client'`. The docs say to use one when you need state, event handlers, lifecycle logic, browser APIs, or custom hooks. The button file from the hooks page is a Client Component. The page that loads the book is a Server Component. The page renders the button and passes <Term id="props">props</Term>.

```
export default async function Page({ params }) {
  const { id } = await params;
  const book = await getBook(id);
  return <TaxButton bookId={book.id} />;
}
```

`getBook` stays on the server. `bookId` is serialized and passed to the client. Do not pass a database client, a secret, or a function that closes over a secret. The docs describe the React Server Component payload as the rendered server tree, placeholders for client components, and the props passed across that boundary. If a prop cannot be serialized, it cannot cross.

Add `'use client'` only on the interactive leaf. A client file that imports a server-only module pulls that module toward the browser or fails the build. Push the data down as props instead of pulling the database up.

## Real example

Two files, two jobs:

```
app/books/[id]/page.tsx          server, loads the book
app/books/[id]/tax-button.tsx    'use client', the click
```

The page does not start with `'use client'`. The button does. If you mark the page as client so the button can live in the same file, the data load moves to the browser. Split the file instead.

</TryIt>

<Mistake>

Putting `'use client'` on the root layout so hooks work everywhere. You have sent the whole tree to the browser and lost the place secrets were allowed to live. Keep the directive on the leaf that actually clicks.

</Mistake>
