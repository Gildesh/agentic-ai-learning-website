## The idea

The browser turns a URL into a request and draws the response. DNS finds the host. HTTP carries the request and the response. The status code is the server's report.

The frontend is HTML for structure, CSS for presentation, and JavaScript for behavior, including the code that sends requests. The visitor controls it. A check that lives only there is not a boundary.

The backend is the program that receives the request, decides, and answers. It reads stored data. It recomputes tax. It returns 200, 400, 404, or 500. You can replay it with curl and no button.

Hosting is a process that stays up under a public name. Localhost is your machine. A git push is not a deploy. Local, staging, and production are three copies. Test writes do not belong on production.

A full-stack map is frontend, backend, store, and, when money moves, a payment company beside the server. An agent fakes the backend when the button changes the page and the network panel stays empty. Debugging reads the request, the status, then the log on the side that failed.

<TryIt minutes={5}>

Answer the four questions, then open the network panel on any site and name one request as frontend-started and server-answered. If you cannot see a status code, reload with the panel open.

</TryIt>

<Mistake>

Calling the whole failure "the frontend" because that is the window you can see. The window draws a status. Read the status before you edit the window.

</Mistake>
