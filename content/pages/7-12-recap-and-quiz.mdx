## The idea

An API is the list of operations another program can call. An endpoint is one method plus one URL. REST, on the previous methods page, keeps the method, the URL, and the status code in view. JSON is the body: objects, arrays, strings, numbers, true, false, and null, with double quotes and no comments.

`fetch` delivers the response, including a 404. You check `response.ok` before `response.json()`. A Next.js route handler in this project awaits `params` and returns `Response.json` with a real status. FastAPI uses a path decorator and raises `HTTPException` for a 404. One of those servers is enough.

An API key goes in the header the vendor documents, on a call your server makes. It does not go in the browser bundle or the query string.

Tables hold rows. A primary key identifies one row. A foreign key points at another table's primary key. SQL's SELECT, INSERT, UPDATE, and DELETE need a WHERE when you mean a subset. An ORM generates that SQL from models. A migration is the file that changes the schema in order. Prisma's `prisma migrate dev`, Drizzle's `drizzle-kit generate` and `drizzle-kit migrate`, and Alembic's `alembic revision --autogenerate` plus `alembic upgrade head` are the commands their docs describe. Read the file before you apply it.

Postgres is the database. Supabase's own overview says each project is a full Postgres database, not an abstraction, and tells you to read about Row Level Security before a client queries a table. A document store copies nested JSON. It is a second system, not a default.
